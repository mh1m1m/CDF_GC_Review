# Architecture decision register

These decisions document current engineering policy; no undocumented personal attribution is implied.

| ID | Decision | Reason and consequence |
|---|---|---|
| ADR-001 | Retain Python, FastAPI, React/TS and SQLite pilot | Existing integrated code and tests are the baseline; replace components only for an evidenced requirement |
| ADR-002 | MAT remains advisory | A learned preference is not authority; preserve independent challenge and human decision boundaries |
| ADR-003 | Separate Black, Red, adjudicator and final-review contexts | Reduce circular confirmation; role labels alone do not prove independent live execution |
| ADR-004 | Separate observation calibration from rule approval | A case decision cannot establish a general methodology; provisional rules remain nonbinding |
| ADR-005 | Fail-closed central release gate | Authentic state/source/decisions/provenance/attestation required before official issue; engineering success does not grant institutional approval |
| ADR-006 | Distinguish provider, simulated, mock, cached and deterministic execution | Mock success cannot establish live quality; local traces are not provider cryptographic attestations |
| ADR-007 | Public source, private institutional material | Only fictional fixtures belong in Git or public CI; approved private data handling is a prerequisite |
| ADR-008 | Local synthetic API stays a pilot | Loopback token authentication and SQLite are not institutional SSO or production assurance |
| ADR-009 | Sign exact replacement proposals | Original-state binding alone cannot stop substitution of proposed wording; require challenge identity and revision digest |
| ADR-010 | Immutable, idempotent profile snapshots | Identical compilation returns stored version; later review actions remove eligibility rather than resurrecting old grants |
