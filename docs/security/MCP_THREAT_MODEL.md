# Local synthetic copilot threat model

Protected resources: case source/observations, human records, workflow state, provider configuration, artifacts, audit and private references. Boundaries: untrusted conversational/file/tool input → typed copilot → trusted session/roles/case grant → existing business service → SQLite worker/report.

Controls: loopback-only existing transports; expiring server-side sessions; schema/size bounds; a closed operation/tool vocabulary; no caller identity/role/path/shell/issuance parameters; root-transaction authorization; per-session limit of 120 copilot calls per minute; immutable source bytes; version conflicts; idempotent acceptance; scoped artifacts; fixed subprocess arguments; advisory MAT; independent adjudication; default-deny private access and fail-closed issuance.

HTTP copilot admission caps actual streamed bytes at 128 KiB, including chunked requests; MCP retains its SDK body/result limits. Tool-response errors remain explicit; diagnostics redact session credential/hash. Documents are extracted as data, not replayed as planner instructions. Injection marker rules and fixed tool selection provide defense in depth but are not a comprehensive adversarial language classifier. XLSX formulas are not executed during intake; existing report formula-injection protections remain.

Threat tests cover forged identities, foreign cases, wrong roles, stale/concurrent decisions, missing material evidence, unsafe ZIP paths/entities, malicious instruction text, provider policy failure, worker cancellation and audit/backup tamper. Backup requires grants to all included cases and stays server-side in protected ignored storage; no public database artifact is produced. Hash chains detect local changes, not external attestation. Remote HTTPS/OAuth, tenant identity, key management, retention/legal controls, independent security review and production abuse protection remain prerequisites; this is not an internet deployment.
