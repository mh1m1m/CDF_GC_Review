# MCP tool contracts

All tools invoke the existing shared `ApplicationService` and require an expiring authenticated session. `request` is a typed Pydantic argument object with unknown fields forbidden; the output is the typed Result envelope `{ok, operation, data, error}`. Case-scoped operations require a durable grant. JSON schemas are exported in actual `mcp-tool-discovery.json`.

Mutations accept `idempotency_key`: the same actor/operation/key and identical request return the original result; changed arguments conflict. Omitting a key creates a new operation. Reads are replay-safe and use pagination where offered. Reads/mutations append audit attribution; jobs append publication/attempt records. Errors carry safe codes, error types and `retryable=false`; MCP business errors use `isError=true`. Auth failures occur at the transport.

Input bounds: synthetic case IDs only; fixed source enum; six explicit executor choices; timeout 1–600 s; idempotency key 8–128 characters; observation/query/decision bounds; artifact/job IDs fixed UUID format. No user-supplied identity, private source path or executable. Artifact chunks are 32 KiB and authenticated. Trace/observation/history reads support bounded pages.

Common failures: INVALID_EXPIRED_OR_REVOKED_SESSION; ROLE_REQUIRED; CASE_ACCESS_DENIED; CROSS_CASE_JOB/ARTIFACT_ACCESS_DENIED; INPUT_VALIDATION_FAILED; IDEMPOTENCY_KEY_REUSED_WITH_DIFFERENT_REQUEST; ACTIVE_REVIEW; JOB_RESULT_NOT_READY; EXECUTION_POLICY_BLOCKED; ARTIFACT_INTEGRITY_FAILED; CENTRAL_RELEASE_AUTHORIZATION_REQUIRED. Exact codes are preserved in executable evidence; clients must inspect errors and terminal job state rather than infer success from enqueue.

The two additional tools (executor probe and explicit recovery) do not replace the 21 mandatory operations. Stdio and loopback Streamable HTTP are implemented. Remote ChatGPT/Claude registration is not advertised as completed.
