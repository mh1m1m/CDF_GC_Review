# Organization responsibility mapping

The existing layout-aware parser reproduced 81 unit candidates and 15 sector groupings from the supplied 92-page source. Original Arabic names/tasks and page references remain in the authorized private registry. The document uses proposed responsibilities; records retain PROPOSED_NOT_APPROVED.

ResponsibilityRecord carries sector/name, tasks, documented internal/external interfaces, source version and page. Process ownership, reporting relationship and DoA cross-references remain unestablished unless explicit source evidence supports them. Departmental responsibility does not create delegated approval authority. A contact box is an interface, not a reporting line.

The public map uses fictional units and source-derived fixture grouping. The UI can filter authority roles, supporting sources, names, sectors, tasks and internal interfaces; the graph offers authority/responsibility projections and source-page details. Its DOCUMENT_GROUPS_UNIT edges describe source grouping only. Authorized private queries use the same provider-independent lookup model. Observation-linked retrieval can attach verified mandate occurrences to an existing case evidence registry without upgrading source approval/applicability.

Candidate/version changes require human reconciliation. No automatic conflict resolution toward broader authority, inferred hierarchy, process ownership or permissive delegation is performed.
